# Fishing Assistant v3

https://github.com/NH4OH-35/Delta-force-s11-auto-fishing/releases/tag/v3.0.0

Windows 图形界面版。按页面顺序设置：**① 设备与按键 → ② 钓鱼流程 → ③ 声音确认与重置**。

请仅在游戏规则允许自动化的情况下使用；使用者自行承担账号限制或处罚风险。

## 启动

1. 解压 Windows 发布包。
2. 双击 **`FishingAssistantV3.exe`**。此版本自带运行环境和三个声音模板，**不需要安装 Python 或依赖组件**。
3. 未获得管理员权限时，先提示“未以管理员身份运行”。点击“确定”后请求 Windows 管理员权限；取消则退出，不会运行钓鱼。仍然只有 GUI，没有常驻命令行窗口。
4. 选择与游戏一致的 Windows 输出设备。
5. 游戏中保留鼠标左键，并把 F6 添加为射击的第二按键。先手动测试 F6 能抛竿、收竿。
6. 点击“开始运行”，在倒计时内切回游戏。F8 或窗口中的“停止运行”按钮可停止。

当前全自动流程针对入门台钓竿。保持游戏在最前面，并开启钓鱼音效。

## 使用体验

- 底部署名：**Created by Nh & GPT-6 Astra**。
- 日志可以缩放：上下拖动设置区与日志区之间的分隔条，也可调整整个窗口大小。默认日志区更大。
- “测试声音 · 5 秒”：只录音，不发送按键；观察下方输入音量，确认所选设备有声音。音量条不是咬钩相似度。
- 运行或测试期间锁定设置；停止后可修改。保存成功显示在窗口内，不再弹出确认对话框。
- “导出日志”：将当前窗口日志保存为文本，方便反馈问题；窗口保留最近约 1,000 行。
- 小窗口可滚动查看设置，开始、停止按钮和署名固定可见。
- 停止后释放全局停止热键；关闭窗口会等当前按键释放后再退出。
- 再次打开时会提示已有程序，防止多个正常运行实例同时发按键。

## 按顺序理解默认流程

| 步骤 | 默认设置 | 含义 |
| --- | --- | --- |
| 1. 抛竿 | 连按两次 F6，第二次延迟 0 秒 | 第一次松开后立即再按一次，用于确保抛竿；可取消勾选，仅按一次 |
| 2. 等待 | 5 秒 | 从最后一次抛竿按键结束起算；这段时间不匹配咬钩声 |
| 3. 监听咬钩 | 匹配阈值 60% | 相似度达到设置值时视为检测到咬钩 |
| 4. 咬钩后收竿 | 0.2 至 0.2 秒 | 固定等 0.2 秒，再按 F6 收竿 |
| 超时兜底 | 单轮最长 20 秒 | 一直未检测到咬钩或未收竿，到时尝试按 F6 收竿；20 秒包含前面的 5 秒 |
| 5. 等待动画 | 随机 7–9 秒 | 结束后重新抛竿，进入下一轮 |

你观察到通常约 7–10 秒上鱼。超时兜底不知道游戏真实状态：错过咬钩窗口后，如果游戏已经恢复待抛竿状态，超时按键也可能变成再次抛竿。

反应延迟、动画等待均可自定义。范围两端相同表示固定等待，不同则在范围内随机。第二次按键延迟为 0 不代表取消第二次按键；取消勾选才会只按一次。

每次按键默认按住 0.12 秒。这与“检测到咬钩后等待 0.2 秒再按键”是两个不同的参数。

## 声音匹配使用百分比

三个声音检测的阈值都以 **0–100%** 输入和显示，默认 **60%**。日志里的相似度也用百分比显示。

- 越高越严格，可能漏掉有杂音的音效。
- 越低越容易触发，也越容易误判。
- 0% 表示没有相似度要求，很容易误判。
- 百分比是音频匹配分数，不是操作成功率。

## 可选：声音确认

进入“③ 声音确认与重置”，按需勾选，两项默认关闭：

- **确认鱼饵已落水**：抛竿前准备录音，只匹配在每次按下 F6 后 **0.25–3 秒内开始**的落水声。使用 `dropped_bait.wav`。
- **确认鱼已拉起**：收竿前准备录音，在收竿按键期间监听拉起确认声。使用 `confirm_pull_fish.wav`。

落水确认默认开始延迟 0.25 秒、最晚出声时间 3 秒；拉起确认时限仍为 3 秒。阈值均为 60%。可单独换模板和调整参数。两个 WAV 是由提供的 M4A 完整转换而来；运行时不需要 FFmpeg。

落水音效如果到第 2.95 秒才开始，程序仍会听完完整音效再判断。最晚出声时间之后会保留“模板长度 + 0.15 秒处理余量”，默认共约 3.98 秒，仍包含在默认 5 秒等待内。界面会检查等待时间是否足够。拉起确认时限必须容纳完整模板，并且不超过最短动画等待。

启用第二次抛竿按键时，每次按下都有自己的 0.25–3 秒出声窗口，任意一次确认成功即可。检测到落水声不会取消已配置的第二次按键。

成功显示“确认成功”，超时未匹配显示“未确认”，并显示最高相似度。没听到不一定代表操作失败，也可能是音量、杂音或阈值导致漏检。

## 可选：确认失败后按 3 → 6 重置

默认关闭。需要先启用至少一项声音确认，并确认游戏中 **数字 3 是刀，数字 6 是鱼竿**。

开启后的触发条件：

1. 抛竿后，在时限内没检测到落水确认声；或
2. 已检测到咬钩并按键收竿，但在时限内没检测到拉起确认声。

触发后结束当前这一轮，按 **3 → 等 0.25 秒 → 按 6 → 等 1.5 秒 → 重新抛竿**。两个等待都能调整。

- 未开启重置：缺少确认音效只记日志，继续原流程。
- 普通超时收竿可能没有鱼；此时缺少拉起确认声只记日志，不触发重置。
- 声音设备读取错误：停止并显示错误，不触发切刀。
- F8 或停止按钮可以中断重置。
- 默认最多连续重置 3 次；之后仍然未确认则停止。正常完成一轮且至少有一项声音确认成功后，计数清零。
- 这只是根据声音推断的恢复操作，不能读取或保证重置游戏真实状态。

## 保存与更新

“保存设置”保存到 `%LOCALAPPDATA%\NhFishingAssistant\gui_settings.json`，点击开始也会保存。更新或移动程序后仍可读取这些设置。可在资源管理器地址栏粘贴 `%LOCALAPPDATA%\NhFishingAssistant` 打开设置目录。启动或界面错误详情保存为此目录下的 `last_error.txt`。

从更早的脚本版本迁移时，可把旧 `gui_settings.json` 放到新 EXE 旁边；仅当还没有 用户设置时读取。要采用本版默认值，可点击“恢复默认”再保存。设备和声音文件选择不会被此按钮更改。运行期间需先停止才能修改设置。

界面显示百分比，配置文件内部仍保存 0–1 的小数，以兼容旧设置。不要把旧配置中的 0.60 手动改成 60。

```text
FishingAssistantV3.exe
README_GUI.md

```

`THIRD_PARTY_LICENSES` 不是运行依赖，EXE 不读取它；对外分享程序时请保留这些第三方许可说明。

声音模板已内置，也可以在界面中选择自己的 WAV。EXE 支持 Windows 64 位。当前发布包未做代码签名。

## 源码版（开发者）

源码包单独提供。安装 Python 3.12 后运行 `py -m pip install -r requirements-gui.txt`，然后双击 `start_fishing_bot_gui.pyw`，通过 Python 的无控制台模式启动。旧 `.bat` 仅作为兼容入口，点击时可能短暂出现控制台；普通用户直接使用 EXE。

`BUILD_WINDOWS.ps1` 可从源码构建无控制台的单文件 EXE；它会在源码目录内创建独立构建环境，并下载构建依赖。`test_gui_confirmations.py` 是离线测试，不会向游戏发送按键。

音频监听绑定所选 Windows 输出设备的 ID。如果其他应用的声音仍混入，请检查 Windows 音量混合器的应用输出、驱动混音或设备镜像设置。

本版已进行离线流程测试；游戏里的音效识别、双按键和 3/6 切换效果需要实际测试。
